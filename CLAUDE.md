# Relay — session instructions

Read `README.md`, `docs/ARCHITECTURE.md` and `docs/STATUS.md` before changing
anything. `docs/DEVELOPMENT.md` covers building and testing each app.

## Decisions already made — don't reopen them

- **The Android receiver is native Kotlin.** Don't propose React Native,
  Capacitor or Flutter for it. The reason is in `docs/ARCHITECTURE.md`:
  AccessibilityService and NotificationListenerService have a system-managed
  lifecycle and must stay alive for days.
- **The controller is Expo with Continuous Native Generation.** `android/` and
  `ios/` are generated by `expo prebuild` and never committed or hand-edited;
  native configuration goes in `app.config.ts` and config plugins.
- **There is no iOS receiver.** iOS has no equivalent of AccessibilityService.
  The controller is cross-platform, the receiver is Android plus the browser
  extension.
- **No `isAccessibilityTool` in the manifest.** It would be a false declaration.
  See `docs/DISTRIBUTION.md`.
- **No root.** Shizuku exists as an optional last executor; nothing may depend
  on it. See `docs/SHIZUKU.md`.

## Invariants

- `Codec.canonicalize` exists in TypeScript (`packages/protocol/src/codec.ts`)
  and Kotlin (`core/Codec.kt`) and must produce identical bytes. If you change
  one, change the other, regenerate vectors with `npm run vectors -w
  @relay/protocol` and update `CodecTest.kt`. A divergence shows up only as a
  bare `signature` in the logs. The same applies to the MQTT codec
  (`mqttCodec.ts` ↔ `MqttCodec.kt`) and WebRTC signalling (`signable()`).
- **Fullscreen recipes are data, not code.** They go in
  `apps/receiver-android/app/src/main/assets/recipes.json` (and, for the
  browser, `apps/browser-extension/src/sites.json`). Never move a strategy into
  Kotlin or TypeScript: they break with every update of the target apps and must
  be editable without recompiling.
- **Every envelope carries a unique `id` and the `DedupeWindow` uses it.** It is
  the only thing that stops a command duplicated across two paths from running
  twice. Don't remove it "to simplify".
- **Every frame is signed, heartbeats included.** Receivers drop unsigned frames.
- **Adding a transport = one class implementing `Transport` + one line in each
  candidate list** (controller registry, `RelayForegroundService.bootstrap()`,
  extension `offscreen.ts` if it applies). If a transport change touches
  commands, UI or the execution chain, the abstraction has been violated.
- **Shizuku commands are fixed argv templates.** Recipes may name a key code,
  never a command. Nothing goes through `sh -c`.
- Code comments in English. Documentation (all Markdown) in English. User-facing
  strings in the apps stay in Italian.

## How to work

- One step at a time; don't move on until the current step builds and has been
  verified (on the emulator bench where possible — see `docs/DEVELOPMENT.md`).
- Before writing new code, say what you're about to do and why.
- Don't invent view ids or labels for recipes: read them from a real device
  with `adb shell uiautomator dump`.
- Keep `docs/STATUS.md` honest: what was verified, how, and what wasn't.
